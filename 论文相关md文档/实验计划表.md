## 0. 使用原则

这份表默认按照你当前已经确认的真实机器人环境来设计：

- 当前主任务：`bi_so101_handover_cube`
- 当前硬件：双臂 SO101、三相机、7 自由度
- 当前主链：`demo -> SFT -> HIL rollout -> value train -> value infer -> ACP train -> redeploy`

为了保证实验能做成，我建议分两档：

1. **最低可投稿实验集**
   - 1 个真实任务
   - 3 个评测场景
   - 6 组核心 baseline

2. **增强版实验集**
   - 2 个真实任务，或者 1 个真实任务 + 2 个困难评测场景
   - 更完整的 ablation 和 human budget 分析

如果短期内没有第二个真实任务，不要硬等。  
最现实的方案是：

- 用 `bi_so101_handover_cube` 作为主任务
- 再构造：
  - `perturbed init`
  - `forced recovery`
  - `reduced monitoring budget`

这三种评测场景同样足够支撑论文主结论。

## 3. 指标定义与编号

建议所有实验指标先编号，不然后面很容易写乱。

| 指标 ID | 名称 | 说明 | 主要用于 |
| --- | --- | --- | --- |
| `K1` | Success Rate | 任务成功率 | 主结果 |
| `K2` | Avg Episode Length | 平均 episode 时长 / 步数 | 效率 |
| `K3` | Intervention Frame Ratio | intervention 帧占比 | 人类成本 |
| `K4` | Intervention Count / Episode | 每条 episode 的接管次数 | 人类成本 |
| `K5` | Recovery Success Rate | 接管后是否成功回到成功轨迹 | correction |
| `K6` | Post-Intervention Success | 发生接管后 episode 最终成功率 | correction |
| `K7` | Monitoring Time | 人类持续监控时间 | deployment |
| `K8` | Success Under Fixed Budget | 固定人类预算下成功率 | deployment |
| `K9` | Intervention Precision | request-for-help 精度 | query |
| `K10` | Intervention Recall | request-for-help 召回 | query |
| `K11` | Correction Gap | `||action - policy_action||` 的统计量 | 分析 |
| `K12` | Advantage-Label Quality | 新标签与 success/recovery 的相关性 | relabeling |

### 3.1 指标优先级

主文最关键指标建议固定为：

- `K1` Success Rate
- `K5` Recovery Success Rate
- `K7` Monitoring Time
- `K8` Success Under Fixed Budget

这些指标最能支撑三条方法线的统一结论。
